## 0. Critique of Stage 14

The spec is complete and implementable, but consolidating it made one thing undeniable: **the hard part is now execution, not design.** Fourteen stages produced a coherent paper standard; every remaining risk that can *kill* `.sarib` (RH2, RA1, RA2, RD1, RL2) is empirical and unaddressable on paper (register §10). Stage 15's honest job is therefore not to declare victory but to (a) draw the v1.0 scope line tightly enough to be shippable, (b) make freeze *conditional* on measured evidence, and (c) hand off a project that resumes from files alone. Overclaiming here — calling a paper design "done" — would itself be the drift the charter warns against. No principle reversed.

## 1. What v1.0 is

`.sarib` v1.0 is **an open standard for an AI-native knowledge representation language**: one canonical semantic source of truth — a labeled property graph whose containment spanning-tree serializes as a readable Markdown-superset document — that humans author as prose-plus-light-structure, agents edit atomically by id, and both project into every view (document, outline, graph, board, timeline, table, slides, context window) without translating between formats.

The complete v1.0 stack, each layer specified and cross-consistent:

| Layer | v1.0 content | Stage |
|---|---|---|
| Data model | one node kind + two edge families + identity + 10 invariants | 4 |
| Semantics | 8-kind std vocabulary, edge semantics, self-hosted schemas, resolution | 5 |
| Traversal & query | one parameterized walk; decidable filter; self-hosted queries; read/write bridge | 6–7 |
| Operations | 8 primitives + composites; convergent (SEC); optimistic concurrency | 8 |
| Serialization | canonical JSON form; snapshot+op-log; safety; partial load | 9 |
| Author syntax | CommonMark-superset (Candidate A); business-card grammar | 10 |
| Validation | 3 tiers, forgiving+deterministic, self-hosted diagnostics | 11 |
| Projection | (query, template) views; live-vs-terminal; spatial cues | 12 |
| Reference impl | 6 components; ≤1000-LOC parser; MCP+CLI consumer; harness; corpus | 13 |
| Specification | consolidated, conformance levels, compatibility contract | 14 |

**Mapped to the user's goal statement** (the finish-line brief): *minimal tokens* → atomic ops + subgraph queries (D-002/D-033), not surface tricks; *fast read/write* → bounded queries + id-addressed deltas (D-028/D-036); *perfect interpretation* → deterministic parse + canonical form + closed-world validation (D-041/D-049); *scalable* → partial/streaming load + append-only log (D-042/D-044); *versatile, linear+non-linear+tree* → one graph, document = spanning-tree, 13 traversals as presets (D-026); *spatial idea / spread & dimensions* → derived legibility cues, skeleton-before-detail (D-047/D-054); *emphasis, hierarchy, importance* → headings/nesting + importance-as-field (D-046/D-048). Every clause of the goal maps to a ratified decision.

## 2. Scope: in v1.0

Core model; standard vocabulary v0 (8 kinds); the operation vocabulary; the canonical form + op-log + JSON isomorphism; Candidate-A author grammar; three-tier validation; the projection contract with **three reference projections built** (document, outline, graph — the charter's v1 cap, R3/RP2); the MCP server + CLI consumer; the benchmark harness; the conformance corpus; the compatibility contract.

## 3. Scope: deferred (named, not forgotten)

Deferred to post-v1 companion specs, each with a logged reason:

- **Intra-node text CRDT** (fine-grained content merge) — v1 uses per-node LWW (RM4/RM18).
- **Cryptographic signing / trusted provenance** — v1 provenance is a claim, not a proof (RS4).
- **The compact profile** (Candidate B as a lossless dense encoding for agent-to-agent exchange) — v1 default is Candidate A (D-045).
- **Domain vocabularies** (`sarib-software`, `sarib-design`, …) — v1 ships only `std` (D-021).
- **Real-time collaboration server / live store** — v1 is file-as-truth; the op-log makes this a clean later addition (RM8/D-042).
- **GUI editor** — v1 ships MCP+CLI; rich editors are ecosystem work.

## 4. The freeze gate (v1.0 is conditional on measured evidence)

**v1.0 must not be frozen on paper.** Before ratification, the reference implementation must run the benchmark harness (Stage 13 §5) and clear the success criteria; the grammar's glyphs must be tokenizer-verified (RA11). The gate:

| Gate | Metric | Target | Risk retired |
|---|---|---|---|
| G1 edit economy | tokens: op vs regenerate (S2) | ≤1% | RA2 (partial) |
| G2 agent comprehension | relationship-query accuracy vs Markdown (S4) | strictly better at ≤ tokens | RA1, RA2 |
| G3 human readability | cold structural comprehension (S3) | ≥90% | RH1 |
| G4 implementability | parser LOC / build (S6) | weekend / ≤1000 LOC | — |
| G5 merge safety | concurrent non-overlapping edits, plain git 3-way (S5) | ≥95% auto, 0% silent corruption | RM13/RM18 |
| G6 round-trip | model→view→model, ≥5 views (S1) | 100% semantic equality | — |
| G7 cache | prefix survival under an edit loop (S7) | high hit-rate | RA4 |
| G8 glyphs | chosen sigils single-token (RA11) | single-token in target tokenizers | RA11 |

If G1/G2 fail, the thesis is wrong and the design changes — not the benchmark (Rule 6). This gate is the project's intellectual honesty made procedural: the existential risks are retired by measurement or the standard doesn't ship.

## 5. Governance (RG1)

Ships with v0.1 to avoid the Markdown-CommonMark governance vacuum (Stage 2 §2.2):

- **Frozen core, versioned vocabularies** (D-059/D-025): the core grammar and model don't change; extension happens in namespaced vocabularies with semver.
- **Conformance-corpus-as-truth** (D-057/§10 spec): "conforming" is defined by the test corpus, not any implementation (RM22).
- **An explicit extension process:** anyone may publish a namespaced vocabulary; a small stewarding group curates the `std` namespace and the corpus; core changes require a new major and a migration note. (Concrete governance body is an ecosystem decision, flagged RG1 — the *mechanism* is specified; the *institution* is not yet chosen.)

## 6. Adoption path (RD1/RD5)

The carrier is the LLM+agent stack plus Markdown renderers (P6). The path, one file at a time:

1. A `.sarib` file **is** a Markdown file — it renders today, everywhere, with structure degrading to harmless text (D-045). Zero-cost first adoption.
2. The **MCP server** makes the user's own agent the guaranteed first consumer (RD5): every enriched fact pays off immediately (the schema.org/Wikidata incentive, Stage 2 §2.1) — the RH2 mitigation.
3. The **CLI** makes it a good git citizen (clean diffs, `fmt`, `diff`) — the developer on-ramp.
4. Agents write via the **JSON isomorphism** through existing structured-output tooling (D-041/RA1) — no new model training needed.

Adoption is designed to need *no network effect*: the format is useful to a single user with a single agent on day one (RD5).

## 8. What was learned (the intellectual core)

Five findings that would survive even if `.sarib` itself didn't:

1. **The 13 traversals, the projections, and the query surface are one thing** — a parameterized walk over an identified property graph. Expressiveness in the model dissolves apparent feature-sprawl (Stages 6–7).
2. **Round-trip has a law:** identity + single-owner-per-state-class. Every single-source-many-views system that broke, broke here (Stage 2/RQ5).
3. **The efficiency win is interaction-level, not syntax-level.** Atomic ops addressed by id beat regeneration by orders of magnitude, independent of how terse the surface is (D-002).
4. **Humans won't hand-author structure; the AI era relocates that labor to the agent** — which is the actual reason an AI-native format is newly possible (D-010).
5. **The lethal risks are human, distributional, and safety-related, not technical** (register §10). The language was the easy part.

## The finish line

The brief asked whether we could *design a new foundational language for human–AI collaboration that could remain useful for decades.* Fifteen stages later, the answer on paper is **yes, and here is exactly what it is** — a complete, cross-consistent, evidence-grounded specification with a defined path to proof. What remains is not more design; it is building the thing and measuring it against the baseline. The design honored its own discipline to the end: semantics before syntax, evidence before assertion, critique before ratification, and integrity before cleverness.

Store knowledge once; render it infinitely. Touch it atomically; never regenerate what you can address. Semantics are canonical; everything else is a projection. That is `.sarib`.
