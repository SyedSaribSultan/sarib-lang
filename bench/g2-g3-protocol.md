# G2 & G3 — protocols + indicative results

**Date:** 2026-07-19 · G2 = agent accuracy/cost vs Markdown (S4) · G3 = cold human readability (S3)
Both gates require external subjects (multiple LLMs via API; human raters). This doc fixes the protocol so the run is turnkey, and records the indicative measurements already possible.

## G2 protocol (rigorous run — needs API keys)

- **Corpora:** (a) the 10k-token synthetic KB (`bench/run_gates.py gen_kb`), (b) the dogfooded risk register — each in two renditions holding *identical knowledge*: `.sarib` (typed) and plain Markdown (structure flattened to prose/headings, no typed fields/edges).
- **Questions:** 30 per corpus, three classes: single-hop lookup ("what is X's due date"), relationship/multi-hop ("what must happen before X", "who owns what X depends on"), aggregate ("how many open high-impact risks").
- **Conditions:** (1) Markdown whole-file in context; (2) `.sarib` whole-file; (3) `.sarib` + bounded query result only (the intended agent loop).
- **Subjects:** ≥3 model families (frontier + small), ≥2 runs each, temperature 0.
- **Metrics:** exact-match accuracy; input tokens per question; accuracy-per-1k-tokens. **Pass (S4):** condition (3) strictly beats condition (1) on accuracy at ≤ its token cost.
- **Bias controls:** question order shuffled; renditions generated by script (no hand-tuning); graders blind to condition.

## G2 indicative results (measured today — token side only)

Real project data (dogfooded risk register, 70 risks, 149 nodes):

| Question | Markdown context needed | `.sarib` bounded query result | Reduction |
|---|---|---|---|
| Q1 high-impact open risks | 6,652 tokens (whole file) | **230 tokens** (9 nodes) | **29×** |
| Q3 mitigated risks | 6,652 tokens | 981 tokens (35 nodes) | 6.8× |
| Q2 (deliberately weak filter) | 6,652 tokens | 3,659 tokens (70 nodes — filter matched all) | 1.8× |

Honest notes: Q2 shows the reduction depends on filter selectivity — a bad query degrades toward whole-file cost (never above it). The *accuracy* half of G2 is unmeasured until the API run; the designer self-testing accuracy would not be evidence (RP3/Rule 6 discipline).

Write-side economy is already gated: **G1 measured 0.50%** (50-token guarded op vs 10,040-token regeneration — a 200× reduction; `bench/gate-report.md`).

## G3 protocol (needs human raters)

- **Subjects:** ≥10 raters unfamiliar with `.sarib`; no docs given (cold read, S3).
- **Material:** a 2-page `.sarib` file (Candidate A) with types/fields/edges present.
- **Task:** 10 structural questions ("how many tasks are open?", "what does X depend on?", "where would you add a new task?"); 10-minute limit.
- **Pass (S3):** ≥90% mean accuracy; secondary: subjective readability ≥4/5; comparison arm with the same knowledge as plain Markdown to measure the *cost* of the added marks (RH8 signal).
